## Fix 1 — CRITICAL: OIDC idToken signature verification (JWKS / RS256)

**Before:** `external-login` accepted either `accessToken` (calling the provider
`userinfo` endpoint — which does NOT validate token audience, so a token issued
to a different app could be replayed) or `idToken` decoded with an UNSIGNED
base64 decode (`profileFromIdToken` → `decodeBase64UrlJson`). An attacker could
forge any email, including an admin email, and mint a session.

**After:**
- Created `src/server/oauth-verify.ts` — a verbatim port of horizon's
  `verifyOidcIdToken(provider, idToken, env)`. Verifies via Web Crypto:
  `alg===RS256` + `kid`, signature against the provider JWKS
  (RSASSA-PKCS1-v1_5/SHA-256, with a 5-min JWKS cache), `exp`, `aud===CLIENT_ID`,
  per-provider `iss`, Microsoft `tid` match (when a concrete tenant is set), and
  rejects `email_verified===false`. Returns `null` on any failure (fail-closed).
- `external-login` now imports `verifyOidcIdToken`, **requires** `body.idToken`
  (400 if missing), runs `const profile = await verifyOidcIdToken(externalProvider, body.idToken, env)`,
  and returns 401 if `null`.
- Deleted dead helpers `profileFromIdToken`, `profileFromAccessToken`,
  `profileFromClaims`, `decodeBase64UrlJson` (and the now-unused
  `splitDisplayName`, which moved into oauth-verify). Dropped the `accessToken`
  path entirely.
- Removed `accessToken` from `ExternalAuthDto` in `src/services/auth.service.ts`
  (idToken only). Updated the OAuth callback (`auth.callback.tsx`) to stop
  passing `accessToken` for both Microsoft and Google — mirrors horizon.

## Fix 2 — HIGH: admin bootstrap gate

**Before:** `syncAdminRole` granted `MasterAdmin` to any email in `ADMIN_EMAILS`
on every register / external-login, with no first-time-only gate.

**After:** Added `masterAdminExists(db)`
(`SELECT 1 FROM user_roles ur JOIN roles r ON r.id=ur.role_id WHERE r.name='MasterAdmin' LIMIT 1`).
`syncAdminRole` now takes a `rawDb: D1Database` param and, before granting
MasterAdmin, `if (await masterAdminExists(rawDb)) return` — auto-grant only at
true first-time bootstrap. Both call sites (register + external-login x2) pass
`env.DB`. Mirrors horizon (including the race-note comment).

## Fix 3 — HIGH: base64UrlEncode UTF-8

**Before:** For string input, `base64UrlEncode` passed the raw string to `btoa`,
which throws on non-Latin1 chars (e.g. "Abdagić").

**After:** `const bytes = typeof input === 'string' ? new TextEncoder().encode(input) : input;`
then builds the binary string from the UTF-8 bytes. Mirrors horizon (`src/server/auth.ts`).

## Fix 4 — MEDIUM: atomic refresh-token consumption

**Before:** SELECT `user_id` by hash, then `DELETE ... WHERE user_id = ?`
(deleted ALL of a user's tokens; check-then-delete race).

**After:** Single atomic statement —
`const nowIso = new Date().toISOString();`
`DELETE FROM refresh_tokens WHERE token_hash = ? AND expires_at > ? RETURNING user_id`,
bound `(tokenHash, nowIso)`, `if (!consumed) return 401`. Deletes only the
presented token, race-free via `RETURNING`. Mirrors horizon.

## Fix 5 — LOW: login timing

**Before:** `if (!user || !user.password_hash) return 401` immediately — leaks
account existence via response latency.

**After:** Added `DUMMY_BCRYPT_HASH` constant and
`await bcrypt.compare(body.password, DUMMY_BCRYPT_HASH)` before the 401 in that
branch, equalizing timing. Mirrors horizon.

## Env vars (`verifyOidcIdToken` audience validation) — fail-closed if missing

`verifyOidcIdToken` returns `null` (rejects external login) when the relevant
`*_CLIENT_ID` is absent — fail-closed is the safe default; the fix is correct
either way. NO secret values are reproduced here.

- `wrangler.jsonc` `vars`: contains NONE of `MICROSOFT_CLIENT_ID`,
  `MICROSOFT_TENANT_ID`, `GOOGLE_CLIENT_ID` (only JWT_ISSUER/JWT_AUDIENCE/
  ADMIN_EMAILS/etc.). For the deployed Worker these must be supplied as
  Cloudflare secrets (`wrangler secret put`), which are not visible in config.
- `.dev.vars` (local dev only): `MICROSOFT_CLIENT_ID` present,
  `MICROSOFT_CLIENT_SECRET` present.
- Missing everywhere visible in the repo:
  - `MICROSOFT_TENANT_ID` — absent → JWKS defaults to `common` and the `tid`
    match is skipped; signature/aud/iss are still enforced. Set it to the real
    tenant GUID to also pin `tid`.
  - `GOOGLE_CLIENT_ID` — absent → Google external login fails closed (rejected)
    until set.
  - `GOOGLE_CLIENT_SECRET` — absent → Google `exchange-code` returns 500.

**Action for user:** ensure `MICROSOFT_CLIENT_ID` and `GOOGLE_CLIENT_ID`
(and ideally `MICROSOFT_TENANT_ID`) are set as production Cloudflare secrets so
external login can validate audience. Do not add secret values to wrangler.jsonc.
